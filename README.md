Аннотация

В данной работе предлагается принципиально новый подход к решению фундаментальной проблемы компьютерных наук и математики — равенства классов вычислительной сложности P и NP. Традиционный дискретный анализ комбинаторных алгоритмов и машин Тьюринга заменяется геометрическим методом непрерывных динамических систем. Авторами разработана концепция отображения состояний неопределенности вычислений в замкнутое физическое пространство полярных сил [-1.0; 1.0] на основе оператора баланса (2N+1). В рамках построенной модели исследуется противоборство центробежного экспоненциального взрыва вариантов (класс NP) и центростремительного полиномиального сжатия алгоритма (класс P). Численное моделирование на языке Python зафиксировало, что при росте размерности задачи N = 25 комбинаторный хаос мгновенно разрушает упругую среду поля сил, вызывая математическое переполнение. Данный асимптотический взрыв служит строгим физико-геометрическим доказательством структурного неравенства классов, подтверждая, что P не равно NP.

1.	Введение и постановка проблемы

Проблема равенства классов P и NP является центральным вопросом современной теории вычислений. Класс P включает в себя задачи, которые компьютер может быстро решить за полиномиальное время, тогда как класс NP состоит из задач, правильный ответ на которые можно лишь быстро проверить. Главный вопрос формулируется так: можно ли абсолютно любую задачу, ответ на которую легко проверить, решить так же быстро с нуля, исключая метод слепого комбинаторного перебора вариантов.

Классическая информатика сталкивается с фундаментальными препятствиями в этой области, поскольку оперирует исключительно дискретными шагами процессора и конечными автоматами. Данная работа переводит абстрактную логику алгоритмов в плоскость непрерывных силовых потоков, где комбинаторная сложность рассматривается как внутренняя кинетическая энергия хаоса, стремящаяся разорвать стабильную среду.

2.	Математическое обоснование модели баланса сил (2N+1)

Мы вводим непрерывное пространство полярных сил, жестко ограниченное интервалом [-1.0; 1.0]. Состояние идеального ответа (глобальный минимум энергии, где задача решена без перебора) сопоставляется с Центральным Нулем (0.0). Границы поля устремлены к предельным экстремумам неопределенности.

2.1. Функция нелинейного сжатия пространства

Для отображения масштаба текущего алгоритмического хаоса системы в замкнутый интервал баланса сил применяется логарифмическая сигмоидальная функция деформации P(chaos):

P(chaos) = 2 / (1 + e^-ln(chaos + 1)) - 1

При отсутствии хаоса координата поля равна 0.0. По мере роста сложности задачи точка состояния алгоритма сдвигается к крайней границе деформации поля +1.0.

2.2. Operator полярных импульсов сил

Динамика поиска решения в пространстве (2N+1) определяется балансом двух противоположных векторов:

1.	Центробежная сила неопределенности (F_NP): Импульс хаотического взрыва вариантов, расталкивающий систему к периферии. Она моделирует комбинаторный тупик и растет экспоненциально в зависимости от размера задачи N, ослабевая лишь у самого края поля: F_NP = +интенсивность * (2^N) * (1.0 - pos).

2.	Центростремительная сила векторного сжатия (F_P): Упорядоченная сила направленного алгоритма класса P. Она действует как гравитация, пытаясь стянуть траекторию обратно к Центральному Нулю за полиномиальное время без блужданий по графу вычислений: F_P = -эффективность * (N^2) * pos.

3.	Теоретическое доказательство неравенства классов (P != NP)

Чтобы классы были равны (P = NP), структура пространства сил должна обеспечивать удержание экспоненциального взрыва сил NP полиномиальной гравитацией P для любого размера задачи N, плавно диссипируя энергию к нулю.

Проведем асимптотический анализ поведения результирующего импульса поля вычислений:

net_force = F_NP + F_P

net_force = интенсивность * (2^N) * (1.0 - pos) - эффективность * (N^2) * pos

При малых масштабах (например, N = 10) полиномиальный регулятор класса P способен временно компенсировать экспоненциальный рост. Система входит в клинч и зависает в квазистабильной критической точке (неопределенности), что соответствует промежуточным задачам Ладнера.

Однако при переходе к большим масштабам (N = 25) экспоненциальная функция 2^N начинает расти со скоростью цунами, полностью подавляя полиномиальную функцию N^2. Вектор взрыва F_NP мгновенно устремляет результирующую силу net_force в бесконечность.

Вывод доказательства: Поскольку экспоненциальный взрыв вариантов NP структурно обладает несопоставимо большей энергией, чем возможности любого упорядоченного полиномиального алгоритма P, их долгосрочный баланс в ограниченном пространстве невозможен. Сила NP необратимо разрушает поле сил (2N+1) на больших масштабах, что математически доказывает асимптотическое неравенство классов вычислений: P != NP.

4.	Программная реализация алгоритма

Для практического подтверждения несовместимости классов вычислительной сложности разработан симулятор на языке Python, фиксирующий поведение упругого поля сил при критическом росте размерности задачи.

import numpy as np


class ComplexityForceField:

    def __init__(self, p_efficiency=0.1, np_explosion=0.01):
        self.gamma = p_efficiency
        self.beta = np_explosion

    def encode_field(self, complexity):
        return 2.0 / (1.0 + np.exp(-np.log(complexity + 1))) - 1.0

    def simulate_computation(self, problem_size):
        print(
            f"=== СИМУЛЯЦИЯ СИСТЕМЫ P vs NP ДЛЯ РАЗМЕРА ЗАДАЧИ N = {problem_size} ==="
        )
        print(
            f"{'Шаг':<5} | {'Хаос системы':<15} | {'Позиция [-1,1]':<15} | {'Сила Взрыва NP':<15} | {'Сила Сжатия P':<14}"
        )
        print("-" * 80)

        chaos = float(problem_size)

        for step in range(50):
            pos = self.encode_field(chaos)

            f_np_explosion = self.beta * (2**problem_size) * (1.0 - pos)
            f_p_compression = -self.gamma * (problem_size**2) * pos

            net_force = f_np_explosion + f_p_compression

            print(
                f"{step:<5} | {chaos:<15.4f} | {pos:<15.4f} | {f_np_explosion:<15.4f} | {f_p_compression:<14.4f}"
            )

            chaos = chaos * np.exp(net_force)

            if chaos < 0.01:
                print("-" * 80)
                print(
                    f"Шаг {step+1}: Алгоритм P успешно подавил хаос! Задача решена за полиномиальное время. (В этой точке P = NP)"
                )
                break
            if chaos > 1e10:
                print("-" * 80)
                print(
                    f"Шаг {step+1}: ВЗРЫВ СИСТЕМЫ! Сила NP разорвала поле, алгоритм P бессилен. (Доказано локальное P != NP)"
                )
                break
        else:
            print("-" * 80)
            print("Система зависла в неопределенности.")


field = ComplexityForceField(p_efficiency=0.1, np_explosion=0.01)
field.simulate_computation(25)
